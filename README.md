# CodeGraph

**Графовый анализатор архитектуры Dart/Flutter-проектов с локальным ИИ-инспектором.**

CodeGraph — десктопное приложение на Flutter, которое сканирует исходники Dart/Flutter,
строит интерактивный граф зависимостей, находит архитектурные аномалии и объясняет их
с помощью локальной языковой модели (Ollama). Исходный код проекта не покидает компьютер:
сканирование, анализ и ИИ-диагностика выполняются локально.

## Возможности

| Возможность | Описание |
|---|---|
| Сканирование проекта | Рекурсивный обход `lib/`, разбор `import`/`export`, разрешение относительных и `package:`-путей |

## Технологический стек

- **Flutter 3.47+ / Dart 3.13+** — UI и бизнес-логика, целевые платформы: macOS, Windows, Linux.
- **provider** — управление состоянием (`ChangeNotifier` + `Provider`).
- **InteractiveViewer + Stack + CustomPaint** — собственная отрисовка графа без сторонних пакетов; раскладка детерминированная.
- **http** — взаимодействие с локальным HTTP API Ollama.
- **file_selector** — системный диалог выбора каталога.
- **shared_preferences** — хранение настроек подключения к Ollama.
- **path**, **intl** — работа с путями и форматирование дат/чисел.

Внешние сервисы и базы данных не используются. Приложение автономно.

## Архитектура

Проект построен по **feature-first**: код разбит на фичи — вертикальные срезы
«данные + логика + интерфейс». Внутри фичи никаких прослоек domain/data/presentation
нет: сущности, алгоритмы, контроллеры и виджеты лежат в одной папке, рядом друг с другом.

```
main.dart — сборка провайдеров (provider + ChangeNotifier)

core/        — общие вещи: палитра, форматтеры, виджеты, AppFailure
app/         — каркас приложения: тема, top bar, композиция экрана
features/    — фичи:
  project_scan/  сканирование Dart-проекта (Isolate) → ProjectGraph
  analysis/      поиск аномалий: циклы, нарушения слоёв, dead code, связанность
  graph/         интерактивный граф: контроллер, раскладка, холст
  inspector/     ИИ-диагностика: Ollama API + офлайн-эвристика
  search/        локальный поиск по графу
  settings/      настройки Ollama (SharedPreferences)
```

Правила простые:

- зависимости идут от виджетов к контроллерам и от контроллеров к сервисам;
- асинхронные операции бросают `AppFailure` — контроллеры ловят его через
  обычный `try/catch` и показывают сообщение в интерфейсе;
- точка входа `main.dart` — единственное место, где создаются контроллеры;
  никакого ручного DI-контейнера нет.

Состав фичи:

```
features/<feature>/
├── <сущности>.dart        # например source_file.dart, project_graph.dart
├── <сервисы>.dart         # алгоритмы и обёртки над внешним миром
├── <контроллер>.dart      # ChangeNotifier для UI
└── *.dart                 # виджеты фичи
```

## Как это работает

### 1. Сканирование

1. Определяется корень проекта: если есть `lib/`, анализируется он, иначе — выбранный каталог.
2. Имя проекта читается из `pubspec.yaml`.
3. Рекурсивно собираются `.dart`-файлы; пропускаются `.git`, `build`, `.dart_tool`,
   платформенные каталоги и сгенерированные файлы (`*.g.dart`, `*.freezed.dart`, `*.gr.dart`,
   `*.mocks.dart`).
4. Из каждого файла извлекаются директивы `import`/`export`.
5. Импорт разрешается в файл проекта:
   - относительный путь — от каталога текущего файла;
   - `package:<имя_проекта>/...` — от `lib/`;
   - внешние пакеты и `dart:` игнорируются.
6. Дубли рёбер удаляются, строится иммутабельный `ProjectGraph` с индексами входящих
   и исходящих рёбер.
7. Сканирование выполняется в `Isolate.run`, чтобы не блокировать UI.

### 2. Классификация слоёв

Слой определяется детерминированно по сегментам пути:

| Слой | Примеры каталогов |
|---|---|
| Presentation | `presentation`, `ui`, `screens`, `pages`, `widgets`, `views`, `theme`, `app` |
| Application | `application`, `bloc`, `cubit`, `controller`, `state`, `di` |
| Domain | `domain`, `entities`, `usecases`, `value_objects` |
| Data | `data`, `datasources`, `repositories`, `models`, `services`, `api` |
| Core | `core`, `common`, `shared`, `config`, `constants`, `utils` |

Файлы вне известных каталогов попадают в `Other`. Каталог `lib/app` — оболочка
приложения (тема, общие виджеты, композиционный корень), поэтому он относится
к Presentation. `main.dart` трактуется как композиционный корень и не считается
нарушением слоёв.

### 3. Анализ аномалий

- **Циклы** — сильно связанные компоненты алгоритмом Тарьяна; петля на себя тоже считается циклом.
- **Нарушения слоёв** — матрица запрещённых направлений: например, `domain` не должен
  импортировать `data`, `presentation` или `application`.
- **Мёртвый код** — файл без входящих и исходящих зависимостей.
- **Высокая связанность** — 8 и более исходящих импортов.
- **Индекс здоровья**: `100 − 12·циклы − 6·нарушения − 4·изолированные − 2·связанность`,
  ограничен диапазоном 0–100.

### 4. Раскладка и отрисовка графа

`computeLayeredLayout` строит детерминированную схему:

1. каждый архитектурный слой получает свою колонку слева направо:
   Presentation → Application → Domain → Data → Core → Other;
2. узлы внутри колонки сортируются по идентификатору, поэтому повторная
   раскладка даёт тот же результат;
3. если в колонке больше 12 узлов, она делится на несколько соседних колонок;
4. размеры берутся из реальных карточек (224×82), между ними остаются фиксированные отступы.

Сцена рисуется без сторонних графовых пакетов:

- `InteractiveViewer` отвечает за зум и панораму;
- `SizedBox` задаёт размер сцены, `Stack` размещает карточки через `Positioned`;
- `CustomPaint` рисует рёбра по тем же координатам, что и карточки;
- `GraphController` хранит один `TransformationController` на всё время жизни
  и ограничивает масштаб/перенос: минимальный масштаб привязан к вписыванию,
  а если в центральной части экрана не осталось ни одного узла, сцена
  сдвигается к ближайшему. Поэтому зум и панорама не оставляют пустой экран.

Силовые алгоритмы (Fruchterman–Reingold) не используются: на проектах из десятков
файлов они дают нестабильные координаты и раздувают граф до десятков тысяч пикселей.

### 5. Локальный ИИ-инспектор

- Статус: `GET /api/tags` (таймаут до 6 с).
- Диагностика: `POST /api/generate` с `format: json`, `temperature: 0.15`, `num_predict: 512`.
- В промпт попадают: имя проекта, путь файла, слой, число строк, списки входящих
  и исходящих зависимостей, результаты детерминированного анализа.
- Ответ парсится устойчиво: снимается markdown-обёртка, поддерживаются русские
  и английские формулировки вердикта и риска.
- При любой ошибке (нет сервера, таймаут, невалидный JSON) включается
  `OfflineInspectorRepository`: он формирует рекомендации на основе типов аномалий
  и честно помечает источник отчёта.

### 6. Интерфейс

- Тёмно-жёлтая палитра (`AppColors`), собственные панели, бейджи и состояния наведения.
  Жёлтый остаётся акцентом выбора, а слой Presentation получил бирюзовый цвет,
  чтобы обычные файлы не выглядели активными.
- Верхняя панель: проект, компактный поиск без подсказок клавиш, статус Ollama,
  настройки, открытие папки. Логотип и название **CodeGraph** — просто марка
  приложения, клик по ним ничего не делает.
- Слева: карточка проекта, метрики, фильтры слоёв, список аномалий. Блоки
  разделены дивайдерами, а «Слои» и «Проблемы» сворачиваются кликом по заголовку.
  Клик по строке слоя включает режим «только этот слой», глазик скрывает
  и показывает слой независимо от режима. У каждой аномалии есть галочка
  «проверено»: проверенные строки тускнеют, а метрики «Аномалии» и «Здоровье»
  пересчитываются по непроверенным.
- В центре: граф с масштабированием, подсветкой циклов/нарушений и режимом фокуса.
  Клик по файлу скрывает остальные узлы и оставляет выбранный, его импорты
  и файлы, которые его используют; линии окрашиваются по направлению связи,
  а плашка сверху показывает только счётчики связей. Снять выделение можно
  кнопкой **×** на панели инструментов или кликом по фону графа.
- Справа: инспектор выбранного файла с зависимостями и ИИ-отчётом; скрытые
  зависимости раскрываются по «и ещё N» в отдельную плашку со всем списком.
  Сверху идут имя файла и теги, затем «Импортирует» и «Используют», ниже —
  аномалии с галочками проверки, а блок локальной диагностики отделён дивайдером
  «Оценка ИИ» и всегда стоит внизу. Выбор файла автоматически раскрывает
  свёрнутый инспектор. Панель сворачивается язычком на левой границе
  и разворачивается тем же язычком; в свёрнутом виде полоса пустая.
- Статус Ollama показывается один раз — в верхней панели; в инспекторе
  он не дублируется.

## Запуск

### Требования

- Flutter 3.47 или новее (Dart 3.13+).
- Для macOS — Xcode с Command Line Tools; для Windows — Visual Studio с C++ toolchain;
  для Linux — `clang`, `cmake`, `ninja-build`, `pkg-config`, GTK 3.

### Установка

```bash
flutter pub get
flutter run -d macos      # macOS
flutter run -d windows    # Windows
flutter run -d linux      # Linux
```

Сборка релиза:

```bash
flutter build macos --release
flutter build windows --release
flutter build linux --release
```

### Первый запуск

1. Нажмите **«Открыть проект»** и выберите корень Dart/Flutter-проекта (папку с `pubspec.yaml`)
   или его `lib/`.
2. Дождитесь сканирования — приложение построит граф и список аномалий.
3. Кликните по узлу, чтобы открыть карточку файла и запустить диагностику.

## Настройка Ollama

1. Установите [Ollama](https://ollama.com) и запустите сервер:

   ```bash
   ollama serve
   ```

2. Загрузите модель (подойдёт любая instruct/coder-модель):

   ```bash
   ollama pull qwen2.5-coder
   ```

3. В приложении откройте **Настройки** (шестерёнка в верхней панели) и укажите:
   - адрес — по умолчанию `http://localhost:11434`;
   - модель — например, `qwen2.5-coder`;
   - таймаут — 30–45 с для небольших моделей, больше для слабого CPU.

4. Нажмите **«Проверить»**. Статус отображается в верхней панели.

Если Ollama не запущена, приложение продолжает работать: анализ графа выполняется
полностью локально, а диагностика переключается на офлайн-эвристику.

> **Приватность.** В модель не передаётся содержимое файлов — только пути, слои,
> количество строк, списки связей и найденные аномалии.

## Управление

| Действие | Результат |
|---|---|
| Колесо мыши | Масштаб графа |
| Перетаскивание | Панорама графа |
| Клик по узлу | Режим фокуса на файле и раскрытие инспектора |
| Клик по фону | Снять выделение и вернуть весь граф |
| Клик по строке слоя | Показать только этот слой (повторный клик — все слои) |
| Глазик у слоя | Скрыть или показать слой |
| Галочка у аномалии | Отметить проверенной и пересчитать метрики |

Глобальных горячих клавиш в приложении нет — управление мышью и элементами
интерфейса.

## Тесты и качество кода

```bash
flutter test
flutter analyze
```

Покрыто тестами:

- разбор директив `import`/`export`;
- разрешение путей и классификация слоёв при сканировании реальной временной папки;
- поиск циклов, нарушений слоёв, мёртвого кода и связанности;
- разбор ответа LLM (markdown, русские формулировки, невалидный JSON);
- локальный поиск по имени, слою и синонимам;
- слоёная раскладка: порядок колонок, сортировка внутри колонки, перенос переполнения,
  детерминированность и пустой граф;
- ограничение панорамирования: граф нельзя увести за экран, масштаб учитывается;
- перетаскивание карточки узла и пустого места: сцена не «уезжает» и узлы не разъезжаются;
- минимальный масштаб привязан к вписыванию: многократное отдаление и колесо мыши
  не превращают граф в неразличимую точку;
- масштабирование вокруг центра вьюпорта и возврат читаемого масштаба при переходе
  к узлу из поиска или инспектора;
- смена фильтра слоя пересоздаёт сцену и снова вписывает её в окно;
- изолированные файлы без импортов остаются на графе, а не теряются при раскладке;
- режим фокуса: клик по узлу оставляет только его и прямые связи, остальные карточки
  не рисуются; кнопка **×** на панели инструментов возвращает все 31 узел;
- плашка фокуса показывает только имя файла и счётчики связей, без кнопки возврата;
- направления связей: `relationTo`/`edgeRelation` различают «импортирует» и
  «используют», карточки и рёбра получают разные акцентные цвета;
- «и ещё N» в инспекторе раскрывает плашку с полным списком зависимостей,
  а строка из скрытой части списка открывает файл в графе;
- инспектор сворачивается язычком на левой границе (половина кнопки лежит
  на графе) и разворачивается им же; в свёрнутой полосе нет подписи и цветной
  точки, а выбор файла раскрывает панель автоматически; в панели нет

## Ограничения

- Разбор импортов выполняется регулярным выражением, а не полноценным парсером Dart:
  условные импорты и нестандартное форматирование могут не учитываться.
- Части `part`/`part of` не моделируются отдельными узлами.
- Слои определяются по путям, поэтому нестандартная структура каталогов может
  потребовать расширения `LayerClassifier`.
- Раскладка колоночная: при сотнях файлов колонки становятся длинными, и для чтения
  требуется масштабирование.
- Ollama не входит в поставку: без неё доступен только детерминированный анализ.
